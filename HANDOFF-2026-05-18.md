## Cambios en el Backend

### Seguridad
- **`SECRET_KEY` sin default** — la app falla al arrancar si no está definida en `.env`. Archivo `.env` creado con clave de desarrollo. Docker Compose actualizado.
- **Rate limiting** en `POST /auth/login` — máximo 10 intentos por minuto por IP (`slowapi`). Instancia compartida en `app/core/limiter.py`.
- **Validación de contraseña** — mínimo 8 caracteres, al menos una mayúscula, una minúscula y un número (validador en `UserCreate`).
- **`UniqueConstraint`** agregado en `AttributeValue(attribute_type_id, value)` para prevenir valores duplicados.
- **CORS** limpiado — eliminado `localhost:3000` que no se usa.

### Performance — N+1 resueltos
| Endpoint | Antes | Después |
|---|---|---|
| `GET /products/` | 1 + N×M queries (1 por variante) | 2 queries: productos + GROUP BY stock |
| `GET /stock/alerts/low-stock` | 1 + N queries (1 por variante activa) | 1 query con OUTER JOIN + WHERE |
| `POST /products/{id}/variants/generate` | 1 query por combinación en el loop | Precarga todos los `AttributeValue` en 1 query antes del loop |

La lógica de stock fue movida del router al servicio (`get_products_with_stock`, `get_product_with_stock`, `get_bulk_stock` en `stock_service.py`).

### Correcciones de código
- **`datetime.utcnow()`** deprecado en Python 3.12 → reemplazado por `datetime.now(timezone.utc)` en 5 archivos: `models/product.py`, `models/stock.py`, `models/user.py`, `services/stock_service.py`, `core/security.py`.
- **`db.rollback()` explícitos** eliminados de `create_sale` — el rollback lo gestiona el scope de la sesión de FastAPI.
- **`SELECT FOR UPDATE`** agregado en `receive_purchase_order` para prevenir doble recepción concurrente (ya existía en `create_sale`).
- **`GET /stock/movements/{id}`** — agregado parámetro `offset` para paginación real.
- **`ProductListResponse`** — schema definido pero nunca usado (código muerto identificado, pendiente de cleanup).

### Infraestructura
- **Migración Alembic inicial** generada (`9bed874e5729_initial_schema.py`). Creados `alembic/script.py.mako` y `alembic/versions/` que faltaban.
- **`docker-compose.yml`** — uvicorn sin `--reload` (2 workers para producción).
- **`docker-compose.dev.yml`** — override para desarrollo local con `--reload`.
- **Seed de usuario** — `lifespan` en `main.py` crea el admin por defecto si no existe.

### Tests
**Antes:** 22 tests, todos en capa de servicios, SQLite, sin medición de cobertura.  
**Después:** 63 tests, 93.92% de cobertura (umbral configurado: 60%).

Archivos nuevos:
- `tests/test_api_auth.py` — 10 tests de integración (login, me, crear usuario, RBAC)
- `tests/test_api_products.py` — 13 tests de integración (CRUD productos, categorías, roles)
- `tests/test_api_stock.py` — 19 tests de integración (stock, ventas, compras, proveedores)
- `tests/conftest.py` — reescrito con fixtures reutilizables: `admin_user`, `operator_user`, `admin_token`, `operator_token`, `product_with_variant`, `variant_with_stock`, `supplier`

Los tokens se generan directamente con `create_access_token` (sin pasar por el endpoint) para evitar el rate limiter en tests.

Correr los tests:
```bash
docker exec stocksync_backend bash -c "cd /app && python -m pytest tests/ -v --cov=app --cov-report=term-missing"
```

## Cambios en el Frontend

### Autenticación — completamente reescrita

**Antes:** Login hardcodeado en cliente, `localStorage.setItem("stocksync-auth", "true")`, ninguna request llegaba al backend con token JWT.

**Después:**
- `src/auth/AuthContext.tsx` — Context con `user`, `token`, `isAdmin`, `login()`, `logout()`. Llama a `/auth/me` al hidratar para cargar el usuario real.
- `src/auth/ProtectedRoute.tsx` — Verifica el JWT real, muestra spinner durante hidratación.
- `src/pages/LoginPage.tsx` — Llama a `authApi.login()`, guarda el token, navega al dashboard. Spinner de carga, mensajes de error del backend.
- Sidebar muestra nombre y rol reales del usuario desde el contexto.

### Providers inicializados

`src/main.tsx` ahora incluye:
- `QueryClientProvider` — React Query estaba instalado pero nunca inicializado
- `AuthProvider`
- `Toaster` (react-hot-toast) — también instalado pero nunca inicializado

## Deuda técnica conocida (pendiente)

### Backend
- `ProductListResponse` en `schemas/product.py` — schema definido, nunca usado en ningún endpoint. Candidato a eliminar.
- `PurchaseOrderStatus.CONFIRMED` — el estado existe en el enum pero no hay endpoint que lo use (salto directo PENDING → RECEIVED).
- Tests de concurrencia (`SELECT FOR UPDATE`) — siguen siendo imposibles contra SQLite. Requieren tests de integración con PostgreSQL real (CI/CD).
- No hay refresh token ni blacklist de tokens JWT. Si un admin desactiva un usuario, el token sigue válido hasta su expiración (8 horas).
- Sin logging estructurado ni trazabilidad de requests.

### Frontend
- No hay error boundary global (un error no capturado en cualquier componente crashea toda la app).
- Las páginas de Productos y Stock no tienen paginación del lado del servidor — cargan todas las variantes. Para catálogos grandes esto escala mal.
- `SalesPage` y `PurchasesPage` no persisten el estado de órdenes pasadas entre recargas (solo muestran las de la sesión actual).
- No hay confirmación antes de eliminar un producto.
- Falta gestión de usuarios desde el frontend (existe el endpoint `GET/POST /users/`).

## Variables de entorno necesarias

```env
# backend/.env
DATABASE_URL=postgresql://stocksync:stocksync@db:5432/stocksync
SECRET_KEY=<mínimo 32 chars, cambiar en producción>
DEBUG=true
ACCESS_TOKEN_EXPIRE_MINUTES=480
```

En producción, `SECRET_KEY` debe ser un string aleatorio seguro. La app falla al arrancar si no está definida.
